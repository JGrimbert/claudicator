## Plan : Alléger le thème de l'interface

---

### 1. Analyse du problème

L'interface est entièrement en mode sombre (dark-only), sans possibilité de basculer. Toutes les couleurs sont des valeurs hexadécimales hardcodées directement dans les blocs `<style>` de chaque composant Svelte — aucune variable CSS ni système de thème n'existe.

**Palette actuelle** : fonds quasi-noirs (`#05050f`, `#07070f`, `#111`), texte gris clair (`#bbb`, `#ccc`), accents violets (`#7c6af7`, `#9181f9`).

**Ampleur du changement** : 11 composants + `+layout.svelte`, aucune abstraction de thème en place.

---

### 3. Stratégie de remplacement

**Approche choisie : variables CSS globales dans `:root`**, définies dans `+layout.svelte`.

Avantages :
- Migration composant par composant, sans tout casser d'un coup
- Permet d'ajouter un toggle light/dark dans le futur en une seule règle CSS (`.light-mode { --bg: #f5f5f5; }`)
- Pas de dépendance externe (pas de Tailwind à ajouter)

**Palette cible (thème clair)** : fond blanc cassé / gris très clair, texte sombre, accents violets conservés mais assombris légèrement pour le contraste sur fond clair.

| Variable CSS | Thème actuel (dark) | Thème cible (light) | Usage |
|---|---|---|---|
| `--bg-deep` | `#05050f` | `#f0f0f5` | Consoles, zones profondes |
| `--bg-base` | `#111` | `#f7f7fb` | Corps principal |
| `--bg-panel` | `#0a0a12` | `#ffffff` | Panneaux, cartes |
| `--bg-subtle` | `#1a1a2a` | `#eaeaf2` | Éléments subtils |
| `--border` | `#1e1e2e` | `#d0d0e0` | Bordures |
| `--border-strong` | `#333` | `#b0b0c0` | Bordures marquées |
| `--text-primary` | `#ccc` | `#1a1a2a` | Texte principal |
| `--text-secondary` | `#888` | `#5a5a7a` | Texte secondaire |
| `--text-muted` | `#555` | `#9090a8` | Texte atténué |
| `--accent` | `#7c6af7` | `#5a4ed4` | Boutons primaires |
| `--accent-hover` | `#9181f9` | `#7c6af7` | Survol boutons |
| `--scrollbar` | `#333` | `#c0c0d0` | Barre de défilement |

Les couleurs de statut (`--status-done`, `--status-running`, `--status-error`) et les couleurs de rôles DiagramViewer restent inchangées (elles fonctionnent sur les deux thèmes).

### 4. Étapes de modification du code

#### Étape 1 — Définir les variables dans `+layout.svelte`
- Ajouter un bloc `:root { --bg-base: ...; --text-primary: ...; ... }` dans la balise `<style>`
- Remplacer `background: #111` et `color: #ccc` du `body` par les variables

#### Étape 2 — Migrer `TopBar.svelte`
- Remplacer `#12121a` (barre de nav), `#1a1a28` (select), `#ccc/#aaa` (textes) par les variables

- Remplacer `#111` (fond ligne), `#161616` (hover), `#bbb/#555` (textes)
- Les couleurs de pipeline (done/current) → variables `--pipeline-done-bg`, `--pipeline-current-bg`

#### Étape 4 — Migrer `AgentInput.svelte`
- Remplacer `#07070f` (textarea bg), `#141414` (bordures), `#777/#bbb` (textes)

#### Étape 5 — Migrer `RunConsole.svelte`

#### Étape 6 — Migrer `IssueList.svelte`

#### Étape 7 — Migrer `IssueAnalysis.svelte`

- **Cas spécial** : mettre à jour le `themeVariables` de Mermaid pour le thème clair (`background: var(--bg-deep)` ne fonctionne pas dans Mermaid — utiliser des valeurs hex correspondantes au thème light)

#### Étape 8 — Migrer `TaskList.svelte`
- Remplacer fonds des panneaux, textes, bordures

#### Étape 9 — Migrer `ProjectSettings.svelte`, `AgentConsole.svelte`, `ArtifactViewer.svelte`
- Même approche, composants moins critiques

#### Étape 10 — Migrer `DiagramViewer.svelte`
- Remplacer fonds (`#06060e`, `#0f0f22`), bordures, textes
- Les couleurs de rôles restent inchangées

### 5. Vérifications et nettoyage final

#### Vérifications fonctionnelles
- [ ] Contraste texte/fond respecte WCAG AA (ratio ≥ 4.5:1) sur les textes principaux
- [ ] Les couleurs de statut (vert/rouge/or) restent lisibles sur fond clair
- [ ] Les accents violets restent visibles et cliquables
- [ ] Le diagramme Mermaid s'affiche correctement avec le thème light
- [ ] Les labels GitHub (couleurs dynamiques) restent lisibles — vérifier l'opacité des bordures

#### Vérifications régressions
- [ ] Pas de couleur hardcodée oubliée (recherche regex `#[0-9a-f]{3,6}` dans les fichiers Svelte après migration)
- [ ] Les animations (pulse du statut "running") restent visibles
- [ ] Le scrollbar custom reste discret
- [ ] Les zones `<code>` / `<pre>` (monospace) ont un fond distinguable du fond général

#### Nettoyage
- Supprimer les éventuelles couleurs dupliquées entre les composants
- Centraliser dans `+layout.svelte` toute variable qui apparaît dans plus de 2 composants

---

**Point de départ recommandé** : commencer par l'Étape 1 (variables CSS dans `:root`) puis valider visuellement sur `TopBar` et `ItemRow` avant de migrer les composants plus complexes comme `IssueAnalysis` (Mermaid) et `DiagramViewer`.
